# Конфигурация

Основной файл: `%ProgramData%\ScadaGuard\config.json`. Полный шаблон находится в `config/config.example.json`.

Идентификаторы агента обязательны. Интервалы и таймауты должны быть положительными; пороги диска упорядочены; максимум сигнала больше минимума; идентификаторы проверок уникальны. `local_api.bind_address` принимает только `127.0.0.1`. Production reporter принимает только HTTPS URL.

Имена процессов и служб, пути, порты, шаблоны логов и сигналы всегда задаются оператором. Значения `configure-*` являются намеренными placeholders и до эксплуатации должны быть заменены. Секретов в JSON быть не должно; токен центрального API читается из `SCADAGUARD_API_TOKEN`.

Секция `discovery` управляет редким read-only сканированием: `scheduled_interval_hours`, расширяемыми `keywords`, `additional_roots`, относительными каталогами логов и всеми scan limits. `confirmed_archive` и `confirmed_logs` добавляются только после проверки оператором. По умолчанию discovery выполняется на первом запуске и затем раз в 6 часов; ручной rescan доступен через loopback API.

Desired configuration с сервера ограничена параметрами мониторинга ScadaGuard. Агент проверяет schema, SHA-256 hash, HTTPS URL и безопасность локальных путей, затем атомарно сохраняет рабочую версию в собственной SQLite. Некорректная версия отклоняется, предыдущая рабочая версия сохраняется, а результат отправляется в `/api/v1/agent/config/status`.
